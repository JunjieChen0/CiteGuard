# 第 5 步：接入 CiteGuard 后的演示运行

> 2026-10-31 · Claude Code 2.1.314 + DeepSeek（`deepseek-flash`）· 条件 S：CiteGuard MCP Server + `skill/citeguard/SKILL.md`
> 运行：`uv run python -m experiments.demo_skill resnet diffusion-crop-disease llm-tcm-prescription`
> 原始记录（含完整工具调用过程）：`experiments/results/demo/*.json`（v2，最终代码）、`experiments/results/demo/v1/`（第一次运行，发现了 CiteGuard 自身的误判）

## 1. 设置

- **提示词**：与第 3 步试跑相同，只删去"不要使用任何工具"一句（S 条件必须允许调用工具；第 8 步 B0 也要改用同一版本，保证可比）。
- **隔离**：每次在临时目录运行，独立配置目录；Skill 复制到临时目录的 `.claude/skills/`；`--allowedTools` 只放行 `mcp__citeguard__verify_references`、`mcp__citeguard__search_papers`、`Skill`，其余工具（Bash、WebFetch、WebSearch……）在无头模式下一律被拒绝。
- **终稿独立核查**：运行结束后用 CiteGuard 再核查一次 Agent 的最终输出，不依赖 Agent 自己的说法。

## 4. 演示中发现的 CiteGuard 问题（已修复）

真实 Agent 写出的格式比第 3 步试跑更多样，第一次运行（v1）暴露了 **CiteGuard 自身的误判**：

| 格式 | v1 误判 | 后果 |
|---|---|---|
| `S.-H. Gao, M.-M. Cheng, …`（首字母在前、带连字符） | 标题被解析成 "S.-H"，判 ❌ | Agent 改用全名格式后通过 |
| `L. Van Der Maaten` | 名字解析成 "L. Van Der"，判 ⚠️ | 同上 |
| `Rutuja S. Magar, …`（全名 + 中间首字母） | 只识别出 1 位作者，判 ❌ | **Agent 删掉了这篇真实相关的论文** |
| `Faritha Banu J`、`Sudhan M B`（首字母在后）、`A. Ezil Sam Leni` | 作者段边界判断错误，判 ❌ | **Agent 删掉了 DiffMamba-FSL 等真实相关的论文** |
| `G.M.A.D. Sirishantha`、`;` 分隔 | 判 ❌ | **Agent 删掉了 LesionDiff** |
| `Saroj Kr. Biswas`（名字缩写） | v2 中判 ❌ / ⚠️ | Agent 换了一篇文献 |

修复后，用最终代码重新核查 6 次运行中 Agent 提交过的全部 **126 条不同条目**：115 ✅、11 ⚠️，11 条 ⚠️ 全部是真实错误（上表 + 占位作者），**没有误判**；第 3 步 79 条标注仍 79/79 一致。

**教训**：误判 ❌ 的危害不只是"多报一条"——Agent 会照报告删掉真实、相关的文献。CiteGuard 对 ❌ 必须比对 ⚠️ 更保守。

## 5. 其他观察

- **Agent 用核查工具"套"完整作者列表**：提示词要求"全部作者"，而 v2 中 `search_papers` 只显示前 6 位作者，Agent 故意提交 "Zhang San, Li Si"、"John Smith" 这样的占位作者，从 ⚠️ 报告的"漏掉作者"里拿到完整名单。已把显示上限提高到 20 位作者，并在题录中加入卷期号。
- **Agent 仍会尝试被禁止的工具**：为了拿卷期页码，试过 `curl`、WebFetch、WebSearch，全部被权限拒绝（每篇 8–9 次）。说明 `search_papers` 的返回信息需要覆盖提示词要求的字段。
- **Skill 是否被显式调用**：v2 三次运行都调用了 `Skill` 工具加载 SKILL.md；v1 的 resnet 没有调用，但仍按同样流程使用了两个 MCP 工具（MCP Server 的 instructions 也描述了流程）。第 8 步需要统计"工具调用率"。
- **CiteGuard 不检查相关性**：终稿 30 条文献从标题看都直接相关，但这是 Agent 的选择，不是 CiteGuard 保证的。

## 6. 速度

冷缓存核查 15 条（多为 arXiv DOI，需要额外找正式发表版本）约 15 秒，约 1 秒/条；瓶颈是 Crossref 检索 1 次/秒的限速，并发查询帮助不大。
