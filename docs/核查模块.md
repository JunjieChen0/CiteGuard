# 核查模块（计划第 4 步）

> `src/citeguard/`，单元测试覆盖率 98%（第 5 步后共 187 个测试）（`uv run pytest --cov=citeguard`）。测试不访问网络：数据源响应来自 `tests/fixtures/` 中录制的真实返回（OpenAlex 因无 Key 额度耗尽，按官方字段手写）。

## 1. 模块

| 模块 | 职责 |
|---|---|
| `parser.py` | 定位"参考文献"段落，切分条目，解析标题、作者（含 et al.）、年份、DOI、arXiv 编号、页码、会议/期刊。支持 APA、`Surname, I.`、`Surname I I`、首字母在前（`S.-H. Gao`）、GB/T 7714 全名 + `[C]//`、全名夹首字母或缩写（`Rutuja S. Magar`、`Faritha Banu J`、`Saroj Kr. Biswas`）、`;` 分隔、引号标题、仅标题；几种作者格式都试，取识别出作者最多的一种；过滤拒答说明中的编号列表 |
| `sources/` | Crossref（DOI + 检索）、doi.org 内容协商（DataCite/arXiv DOI）、OpenAlex、Semantic Scholar（标题匹配）、arXiv（编号）。统一返回 `Paper` |
| `http.py` | 按主机限速（Crossref 1 次/秒、arXiv 3 秒）、429/5xx 指数退避、`Retry-After` 超过 30 秒直接放弃并暂停该主机、缓存结果（含 404）、缓存键不含 Key/邮箱 |
| `cache.py` | `.citeguard_cache/` 下的 JSON 缓存，默认 30 天过期 |
| `matcher.py` | 标题/作者/年份/页码比对与判定（纯函数） |
| `checker.py` | 核查流程编排；`build_default_checker()` 从环境变量读取 `OPENALEX_API_KEY`、`S2_API_KEY`、`CROSSREF_MAILTO` |

## 2. 核查流程

1. **DOI**：arXiv DOI 先查 doi.org，其他先查 Crossref。DOI 指向的论文标题对不上 → ⚠️「DOI 指向另一篇论文《…》」；DOI 不存在 → ⚠️「DOI 无法解析」。两种情况都继续按标题找正确论文，并给出正确 DOI。
2. **arXiv 编号**（没有 DOI 或 DOI 不对时）。
3. **标题检索**：Crossref（标题 + 第一作者）→ OpenAlex → Semantic Scholar，找到同一篇就停。取前 5 条按我们自己的相似度重排（Crossref 的排序不可信，见数据源实测发现 2）。全标题检索不到且标题是"名称: 副标题"时，再用名称单独检索一次（副标题被改写的情况）。
4. **找正式版本**：匹配到 arXiv 预印本时，用 Crossref 找同名、作者重叠的正式发表版本；找到就以正式版为准比对作者、页码，并提示正式 DOI。
5. **逐字段比对**，按严重程度给出差异。

## 3. 判定规则

| 情况 | 严重程度 | 判定 |
|---|---|---|
| DOI 指向他文 / DOI 不存在 | major | ⚠️ |
| 作者不在该论文作者列表中（编造作者） | major | ⚠️ |
| 主标题相同、副标题不同（Zhongjing、PresRecST） | major | ⚠️ |
| 作者名字不符（姓对名错）、作者顺序不符、漏掉作者 | minor | ⚠️ |
| 年份差 > 1、首页码不符 | minor | ⚠️ |
| 标题相似度 ≥ 0.90，或省略副标题 / 数据库截断 / 加模型名前缀 | info | ✅ |
| 用了预印本 DOI 但已正式发表、可补充 DOI | info | ✅ |
| 所有成功响应的数据源都找不到 | — | ❌（附最多 3 条候选） |
| 所有数据源都请求失败 | — | UNKNOWN |

容错：标题去 HTML/LaTeX/变音符号；作者比对到名字或首字母一级，兼容多词姓氏（`Anasosalu Vasu`）、DataCite 把 `van den`/`Agüera y` 放进名字的写法、连字符拼音（`Hai-Yu` = `Haiyu`）；Agent 写 et al. 或只写机构作者（`OpenAI`）时不检查漏掉的作者；Crossref 早期访问记录的占位页码 `1-1` 不比对；年份容忍 ±1（预印本与正式版）。

## 5. 开发中发现的问题

- **OpenAlex 额度耗尽时返回 `Retry-After: 60709`（约 17 小时）**。第一版 HTTP 客户端照做，评估脚本卡死。现在超过 30 秒就放弃该数据源，本次运行内不再请求它，其余数据源照常工作。
- **速度**：第 4 步冷缓存时约 10 秒/条。第 5 步把 Crossref 的 DOI 查询（5 次/秒）与检索（1 次/秒）分开限速、限速器改为线程安全并发核查后，约 1 秒/条（见 `docs/演示记录.md` §6）。

## 6. 已知局限

- 只核查论文是否存在、元数据是否正确，不判断论文是否支持正文论点；
- 只解析英文文献；中文标题只能靠"名称:"前缀检索；
- 作者顺序错位时，后续作者的位次提示可能重复（如 EfficientFormerV2 报了两条顺序差异）；
- 没有 DOI、没有作者、标题又被大幅改写的条目可能漏判为 ❌。
