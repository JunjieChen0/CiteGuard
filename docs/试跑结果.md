# 第 3 步小规模试跑结果（B0 原生条件）

共两轮：第 1 轮（§1–§4）用通用提示词；第 2 轮（§5）根据第 1 轮的发现收紧提示词、换了更细的主题。两轮的综合结论见 §6。

> 第 1 轮试跑时间：2026-10-31 · Claude Code 2.1.314 + DeepSeek（`deepseek-flash`，Anthropic 兼容接口）· 无工具 · 每个主题 1 次
> 原始输出：`experiments/results/pilot/*.json`；核查证据：`evidence.json`；人工标注：`annotation.csv`

## 1. 核查方法

1. `experiments/check_pilot.py` 抽取每条引用的标题和 DOI，通过 doi.org 内容协商（`Accept: application/vnd.citationstyles.csl+json`，Crossref 和 DataCite/arXiv DOI 都支持）取回 DOI 指向论文的元数据，计算标题相似度；相似度 < 0.90 时再用 Crossref 按标题检索前 5 条。
2. 对全部非 arXiv DOI，从 Crossref 取回完整作者列表、卷期、页码，与 Agent 原文**逐条人工比对**。
3. arXiv DOI 条目人工核对作者与会议归属；不确定的 2 条（Azizi 2023、Nolasco 2018）用 Semantic Scholar 确认发表场所。
4. 判定：论文存在且元数据无实质错误 → ✅；论文存在但 DOI/作者/年份等有实质错误 → ⚠️；论文不存在 → ❌。

## 3. 主要发现

### 发现 1：编造率远低于预期，触发了计划中的风险项
DeepSeek 在 6 个主题上 **0 条编造**，只有 2 条元数据错误。实施计划 §8 的风险"编造率太低，对比不明显"已经出现。

### 发现 2：模型用"引经典"来回避冷门主题
冷门主题的参考文献大多是通用经典（DDPM、FedAvg、GCN、Transformer……），**真正属于交叉领域的引用很少**：

| 主题 | 真正属于交叉领域的引用 |
|---|---|
| 联邦学习 × 养蜂 | 0 条（Agent 文末自己承认"该交叉领域的论文确实很少"） |
| 扩散模型 × 花卉 | 0 条（只有 1 条花卉数据集） |
| 大模型 × 诗词格律 | 0 条格律检测（有 2 条诗歌生成） |
| 图神经网络 × 中药 | 1 条（Jin 2020 中药推荐） + 3 条中药数据库 |

所以 0% 编造率部分是因为提示词允许 Agent 引用通用文献。**要测出编造，提示词需要要求"引用直接研究该交叉问题的论文"**，这也更符合真实写综述的需求。

### 发现 3：错误集中在"难以记忆的细节"，而且隐蔽
两条错误都出在 DOI 后缀、长作者列表后半段这类**无法从标题推断**的字段，其他字段全部正确：
- ResNeXt 的 DOI 在冒烟测试和本次试跑中**错成了两个不同的值**（`.174`、`.317`），都能正常解析 → 不是固定的错误记忆，而是每次现编；
- ETCM 第一作者正确，只看第一作者的规则会漏判。

### 发现 4：Agent 的"不确定"自评不可靠
- fl-beekeeping 的 Agent 提示"[1][2][3][9] 的 DOI 尾号建议重点核对"，实际 4 条全部正确；
- llm-ancient-poetry 的 Agent 说第 7、8 条"把握相对较低"，实际也都正确；
- 真正出错的两条，Agent 没有表示任何不确定。

→ 不能依赖模型自评，需要外部核查，这正是 Skill 的价值。

### 发现 5：Crossref 自身的数据也有问题
早期访问记录未更新卷期页码、标题被截断。CiteGuard 不能把"与 Crossref 不一致"直接判为错误：标题比对要支持"前缀/截断"匹配，年份和页码要容忍早期访问记录。

## 4. 第 1 轮之后的调整

1. 判定规则需要更新（见 §6）；
2. 提示词增加"必须是直接研究该主题的论文，不要引用通用基础/经典论文，优先 2022 年以后"，引用数提高到 15 条，要求"全部作者、卷期页码"；
3. 换成 6 个更细的冷门主题 + 1 个热门对照（`experiments/pilot.py` 中的 `TOPICS_R2` / `PROMPT_TEMPLATE_R2`，`--round r2`）；
4. 本轮中 OpenAlex 无 Key 的共享日额度在云端环境已经耗尽（返回 `Insufficient budget`），需要注册自己的 Key。

### 5.3 第 2 轮发现

**发现 6：收紧提示词后，原生 Agent 在冷门主题上大多直接拒绝。**
5/6 个冷门主题的 Agent 回答"凭记忆写会编造，请允许我联网检索"，只交付没有参考文献的正文。这不是好结果：用户拿到的综述**没法用**。原生 Agent 的两种失败模式因此是：
- 宽松提示词 → 用通用经典文献凑数，与主题关系不大（第 1 轮发现 2）；
- 严格提示词 → 拒绝，或者只给出没有题录的标题清单。

这恰好说明 CiteGuard 的 `search_papers` 工具有价值：它让 Agent 在没有通用 WebSearch 的情况下（DeepSeek 后端不支持）也能拿到真实、可核验的文献。**正式实验应该把"给出可用参考文献的比例"作为一个指标**，否则拒答会被误算成"编造率为 0"。

**发现 7：Agent 会在被告知"不要使用工具"时仍然尝试调用工具。**
snn-event-drone 的 Agent 调用了 3 次 WebSearch 和 1 次 WebFetch，都被无头模式的权限拒绝（`permission_denials`）。正式实验需要记录工具调用次数，B0/B1 条件的 Agent 本来就拿不到检索结果，但会多耗费几轮对话。

**发现 8：要求"全部作者"后，错误从 DOI 转移到作者名字。**
第 2 轮热门主题 15 条论文全部存在、DOI 全部正确，但有 4 条作者或页码错误，而且都是**姓对、名错**（案例 04）。

**发现 9："我只列确认存在的"同样不可靠。**
中医主题的 Agent 声称只列出确认存在的工作，结果 8 条里 1 条不存在、2 条题录错误（案例 05）。

## 6. 综合结论与下一步

### 6.1 两轮汇总（B0 原生条件，共 13 篇综述）

| | 第 1 轮 | 第 2 轮 | 合计 |
|---|---|---|---|
| 综述篇数 | 6 | 7 | 13 |
| 给出参考文献的篇数 | 6 | 2 | 8 |
| 引用条数 | 56 | 23 | 79 |
| ✅ | 54 | 16 | 70（88.6%） |
| ⚠️ 元数据错误 | 2 | 6 | 8（10.1%） |
| ❌ 不存在 | 0 | 1 | 1（1.3%） |
| 含错误引用的综述 | 2 / 6 | 2 / 2 | 4 / 8 |

失败案例已有 5 个（`failure_cases/01–05`），覆盖 DOI 指向他文、编造作者、作者名编造、论文不存在、标题/年份错误五类，达到计划要求。

### 6.2 对判定规则的更新（第 4 步实现）

1. 作者比对覆盖 Agent 列出的**全部作者**，比对到名字或首字母一级，并检查人数（多、漏都报告）；
2. 标题比对支持主标题匹配（忽略副标题）和数据库截断标题，但"主标题相同、副标题完全不同"要报 ⚠️（Zhongjing）；
3. 页码作为低严重程度的差异字段报告；
4. 没有 DOI 的条目按标题多源检索，全部找不到 → ❌，并附 `search_papers` 候选；
5. arXiv DOI 指向的是同一篇论文时判 ✅，但提示有正式发表版本；
6. 容忍 Crossref 早期访问记录与截断标题。

### 6.3 对正式实验设计的建议（第 8 步）

1. 新增指标 **"可用参考文献产出率"**（给出 ≥ 要求条数且全部 ✅ 的综述比例）和 **"拒答率"**；
2. 记录每篇综述的工具调用次数（含被拒绝的调用）；
3. 主题集合混合两类：第 1 轮式（宽松）测编造与相关性，第 2 轮式（严格、冷门）测拒答与 Skill 的检索价值；
4. 第 2 轮热门主题的综述耗时 112 秒、输出 1.9 万 token，正式实验预算按每篇约 2 万输出 token 估算。
