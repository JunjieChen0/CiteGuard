# 文献数据源实测（计划第 2 步）

> 实测时间：2026-10-31 · 无 API Key · 本机经代理访问 · 单次延迟约 0.3–1.9 秒

## 1. 测试样本

| 样本 | 内容 | 预期 |
|---|---|---|
| 真 DOI | `10.1109/CVPR.2016.90`（ResNet，CVPR 2016） | 找到 |
| 真标题 | Deep Residual Learning for Image Recognition | 找到 |
| arXiv ID | `1512.03385`（ResNet 预印本） | 找到 |
| Agent 给的 DOI | `10.1109/CVPR.2017.174`（冒烟测试中 Agent 说是 ResNeXt） | 待核实 |
| 编造标题 | Hierarchical Quantum Attention Networks for Few-shot Botanical Segmentation | 找不到 |

## 2. 各数据源结论

| 数据源 | 是否需要 Key | 实测限流 | 结果 | 定位 |
|---|---|---|---|---|
| **Crossref** | 不需要 | DOI 查询 5 次/秒；检索 1 次/秒；并发 1 | 全部成功 | **主数据源** |
| **OpenAlex** | 不需要，但无 Key 时同一 IP 共享每天 $0.10 额度（每次检索约 $0.001，约 100 次/天） | 1000 次/天 | 全部成功 | 第二数据源；**建议你自行注册免费 Key**（$1/天，约 1000 次检索） |
| **Semantic Scholar** | 不需要，但无 Key 时共享限流池 | 间隔 2 秒仍有 4/6 次返回 429 | 成功的请求结果很好 | 有 Key 时作为第三数据源；无 Key 只做兜底 |
| **arXiv** | 不需要 | 连续请求即 429，退避 10 秒后恢复；标题检索出现过 30 秒超时 | 退避后成功 | 只用于引用里带 arXiv 编号的条目 |

### 关键请求示例

```
# Crossref：按 DOI 查 / 按书目信息检索
GET https://api.crossref.org/works/{doi}
GET https://api.crossref.org/works?query.bibliographic={标题+作者}&rows=5

# OpenAlex：按 DOI 查 / 检索
GET https://api.openalex.org/works/doi:{doi}
GET https://api.openalex.org/works?search={标题}&per-page=5[&api_key=...]

# Semantic Scholar：标题最佳匹配（找不到返回 404 "Title match not found"）
GET https://api.semanticscholar.org/graph/v1/paper/search/match?query={标题}&fields=title,authors,year,venue,externalIds

# arXiv：按编号查（返回 Atom XML）
GET https://export.arxiv.org/api/query?id_list={arxiv_id}
```

### 字段对照

| 含义 | Crossref | OpenAlex | Semantic Scholar | arXiv |
|---|---|---|---|---|
| 标题 | `title[0]` | `title` | `title` | `entry/title` |
| 作者 | `author[].family/given` | `authorships[].author.display_name` | `authors[].name` | `entry/author/name` |
| 年份 | `issued.date-parts[0][0]` | `publication_year` | `year` | `entry/published` |
| 会议/期刊 | `container-title[0]` | `primary_location.source.display_name` | `venue` | — |
| DOI | `DOI`（小写） | `doi`（带 `https://doi.org/` 前缀） | `externalIds.DOI` | `arxiv:doi` |

## 3. 实测中的发现

### 发现 1：DOI 真实存在 ≠ 引用正确（首个真实失败案例）
冒烟测试中，Agent 给 ResNeXt（Aggregated Residual Transformations for Deep Neural Networks）写的 DOI 是 `10.1109/CVPR.2017.174`。Crossref 显示这个 DOI **真实存在，但指向另一篇论文**：*Interspecies Knowledge Transfer for Facial Keypoint Detection*（Rashid 等）。正确 DOI 是 `10.1109/cvpr.2017.634`。

- 只检查"DOI 能不能解析"会把它判成正确——**必须比对 DOI 指向论文的标题**；
- 这类错误人眼极难发现（格式、会议、年份全都对），正好说明 Skill 的价值；
- 归入第 3 步失败案例 #1。

### 发现 2：检索结果的第一条不一定是对的
Crossref 检索 "Deep Residual Learning for Image Recognition" 时，原论文排在**第 3 位**，前两条是标题相近的其他论文，三者得分几乎相同（31.90 / 31.87 / 31.85）。→ 不能直接取第一条，要取前 5 条，**用我们自己的标题相似度重新排序**。

### 发现 3：编造的标题也会"搜到东西"
Crossref 和 OpenAlex 对编造标题都返回了看似相关的论文（如 *Few-Shot Semantic Segmentation of Batik Patterns…*）。→ 必须设置标题相似度阈值，否则会把编造误判为真实。Semantic Scholar 的 match 接口直接返回 404，是很好的佐证。

### 发现 4：同一篇论文的年份在不同数据源里不一样
ResNet：Crossref/OpenAlex 记为 2016（CVPR 正式发表），Semantic Scholar 记为 2015（arXiv 预印本年份）；OpenAlex 还把 arXiv 版本单独列为一条（DOI `10.48550/arxiv.1512.03385`）。→ 年份比对需容忍 ±1 年，预印本与正式版本应视为同一篇。

## 4. 对设计的影响（更新到实施计划）

1. **判定规则新增**：给了 DOI 时，先查 DOI，再比对 DOI 指向论文的标题；标题对不上 → ⚠️ MISMATCH（"DOI 指向其他论文"），并用标题检索找出正确 DOI。
2. **检索顺序**：DOI → Crossref 检索（取前 5 条重排）→ OpenAlex 检索 → Semantic Scholar match（有 Key 时）→ arXiv（仅限带 arXiv 编号的条目）。
3. **限流处理**：每个数据源单独限速（Crossref 检索 1 次/秒；arXiv ≥3 秒）+ 遇 429 指数退避重试 + 本地缓存。
4. **失败兜底**：所有数据源都因网络或限流失败时判为 `UNKNOWN`，不判为编造。

## 5. 需要你做的（可选，但建议）

- **OpenAlex 免费 Key**：在 https://openalex.org/settings/api 用你自己的邮箱注册，写入 `.env` 的 `OPENALEX_API_KEY`。
- **Semantic Scholar 免费 Key**：在 https://www.semanticscholar.org/product/api#api-key-form 申请，写入 `.env` 的 `S2_API_KEY`。审批可能需要几天，可以先申请。
- Crossref 支持在请求里带上邮箱进入"礼貌池"（更稳定），是否使用由你决定；不配置也能用。
