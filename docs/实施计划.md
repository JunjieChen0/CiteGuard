# CiteGuard：学术引用核查 Skill —— 实施计划

> 课程：信息技术前沿与综合素养 · 大作业方向二（Agent Skill 开发）
> 版本：v0.1（2026-10-30，待确认）

## 1. 要解决的问题

Agent 写综述/调研报告时会**编造参考文献**：论文根本不存在，或作者、年份、DOI、期刊写错。读者很难发现，危害大。

本作业要证明三件事：
1. 这个问题**真实且普遍**（≥5 个真实失败案例 + 编造率统计）；
2. CiteGuard Skill 能**有针对性地**解决它（核查 → 标注 → 交回 Agent 修正）；
3. 接入后**指标确实变好**，而且比"只改提示词"更好。

## 2. 技术选型（已核实）

| 项 | 选择 | 说明 |
|---|---|---|
| Agent 框架 | Claude Code 2.1（无头模式 `claude -p`） | 本机已装 |
| 后端模型 | DeepSeek（Anthropic 兼容接口） | `ANTHROPIC_BASE_URL=https://api.deepseek.com/anthropic`，官方文档已确认支持 Claude Code |
| Skill 形态 | MCP Server（核查工具）+ Claude Code Skill（`SKILL.md`，规定何时调用） | MCP Server 用 Python `mcp` SDK（本机 1.26） |
| 文献数据源 | Crossref、OpenAlex、Semantic Scholar、arXiv | 均有免费接口；**第 1 周需实测限流与是否需要 Key** |
| 语言/环境 | Python 3.11 + uv | |

> 注意：Claude Code 自带的 WebSearch 是 Anthropic 服务端工具，DeepSeek 后端不支持，所以基线 Agent 只能凭模型记忆写引用——这正是要测的场景。

## 3. 系统设计

```
用户：写一篇关于 X 的短综述（含 8–10 条参考文献）
        │
        ▼
 Claude Code（DeepSeek 后端）写初稿
        │  SKILL.md 规定：输出参考文献前必须调用 verify_references
        ▼
 ┌──────────── CiteGuard MCP Server ────────────┐
 │ 1. parse：从文本中抽取每条参考文献            │
 │    （标题 / 作者 / 年份 / venue / DOI / arXiv）│
 │ 2. lookup：按 DOI → arXiv ID → 标题 依次检索   │
 │    Crossref → OpenAlex → Semantic Scholar     │
 │ 3. match：标题相似度 + 作者/年份比对           │
 │ 4. 判定：✅ VERIFIED / ⚠️ MISMATCH / ❌ NOT_FOUND│
 │ 5. 输出结构化报告（含正确元数据、候选替代文献）│
 └──────────────────────────────────────────────┘
        │
        ▼
 Agent 按报告修正：⚠️ 用数据库元数据改正；❌ 删除或换成检索到的真实文献
        │
        ▼
 再调用一次核查，全部 ✅ 后输出终稿
```

### MCP 工具接口

| 工具 | 输入 | 输出 |
|---|---|---|
| `verify_references` | `text`：含参考文献列表的文本 | 每条：`status`、原始条目、匹配到的元数据、差异字段、置信度 |
| `search_papers` | `query`、`limit` | 真实论文列表（供替换 ❌ 条目） |

### 判定规则（初版，实验中调参；第 2 步实测后更新，见 `docs/数据源实测.md`）
- 给了 DOI 时，先查 DOI，**再比对 DOI 指向论文的标题**；标题对不上 → ⚠️（DOI 指向其他论文），并按标题检索找正确 DOI；
- 检索结果取前 5 条，用标题相似度重新排序，不直接信任第一条；
- 标题归一化（小写、去标点）后相似度 ≥ 0.90 视为同一篇；预印本与正式发表版本视为同一篇；
- 同一篇 + 第一作者姓氏一致 + 年份差 ≤ 1 → ✅；
- 同一篇但作者/年份/DOI 不一致 → ⚠️，并列出差异字段；
- 所有数据源都找不到相似度 ≥ 0.90 的论文 → ❌；
- 网络失败 → `UNKNOWN`（单独统计，不算编造）。

## 5. 实验设计

### 5.1 三种对比条件
| 条件 | 说明 | 作用 |
|---|---|---|
| **B0 原生** | Claude Code + DeepSeek，不加任何东西 | 基线 |
| **B1 仅提示词** | 提示词加上"请确保参考文献真实存在，不确定就不要写" | 回应 PPT 反面教材"只换提示词"——证明 Skill 不是提示词能替代的 |
| **S 加 Skill** | 接入 CiteGuard MCP + SKILL.md | 本方案 |

可选消融：**S-mark**（只标注、不让 Agent 修正），用来区分"检测"和"修正"各贡献多少。

### 5.2 测试集
- 25 个主题：课程内容（CNN、ResNet、Transformer、GAN、扩散模型、强化学习……）+ 若干冷门主题（冷门主题更容易编造）；
- 每个主题要求 8–10 条参考文献 → 每种条件约 200–250 条引用；
- 每个条件每个主题跑 1 次（预算允许时跑 3 次取平均，降低随机性）。

### 5.3 指标
| 指标 | 定义 |
|---|---|
| 编造率 | ❌ 条数 / 总引用数 |
| 元数据错误率 | ⚠️ 条数 / 总引用数 |
| 可验证率 | ✅ 条数 / 总引用数 |
| 需人工修改条数 | 每篇综述中仍需人改的引用数 |
| 代价 | 每篇的耗时、Token/费用、工具调用次数 |

### 5.4 关键：避免"自己给自己打分"
如果用 CiteGuard 自己的判定来算 CiteGuard 的效果，结论是循环论证。因此：
1. **人工标注金标准**：从 B0 输出中抽取约 100 条引用，人工逐条在 Google Scholar/DOI 网站核实，标注真实标签；
2. 用金标准计算 **CiteGuard 自身的精确率/召回率**（它会不会把真论文误判成编造、漏掉编造）；
3. 最终各条件的指标 = 自动判定 + 对所有 ❌/⚠️ 条目人工复核。

## 6. 分步实施与验证

| 步骤 | 内容 | 验证方式 |
|---|---|---|
| 1 | 用 DeepSeek Key 配置 Claude Code，`claude -p` 跑通一次 | 能输出综述文本 |
| 2 | 实测 4 个数据源接口：限流、是否需要 Key、返回字段 | 记录在 README，写好请求示例 |
| 3 | 收集 ≥5 个失败案例 + 小规模试跑（5 个主题）估计编造率 | `failure_cases/` 有截图和根因分析；若编造率过低需换更冷门的主题 |

| 5 | 实现 MCP Server + SKILL.md，Claude Code 中手动跑通 | 演示一次完整的"发现 → 修正"流程 |
| 6 | 画流程图 | `docs/流程图.png` |
| 7 | 人工标注金标准（约 100 条） | 标注表完成，算出 CiteGuard 精确率/召回率 |

## 8. 风险与应对

| 风险 | 应对 |
|---|---|
| DeepSeek 编造率太低，对比不明显 | 加冷门/交叉主题、要求更多引用；如实报告也是结论 |
| 数据源限流或需要 Key | 本地缓存 + 多源回退；Semantic Scholar 可申请免费 Key |
| Agent 不按 SKILL.md 调用工具 | 统计"调用率"作为指标；必要时在 Skill 中强化触发条件 |
| 真论文在数据库里查不到（误判为编造） | 多源检索 + 人工复核 ❌；在报告中写明误判率 |
| 中文文献无免费接口 | 明确限定为英文文献，写入适用边界 |
| API 费用 | DeepSeek 便宜；先用 5 个主题小规模试跑估算后再全量 |

## 9. 适用边界（报告中要写）
- 只覆盖英文学术文献；
- 只验证"论文存在且元数据正确"，不验证"论文是否支持文中论点"（可作为扩展：用摘要粗判）；
- 依赖公开数据库的收录范围与可用性。
